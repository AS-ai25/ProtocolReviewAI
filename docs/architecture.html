Multi-Agent Clinical Trial Protocol Review System
4 agents on LangGraph · shared Blackboard · every finding = page quote + guideline code + verification status · reports and email to the committee coordinator
Automatic intake. Google Drive folder (Make.com / n8n: Watch Files → Download → HTTP POST) or email inbox (IMAP poller) → POST /webhook/protocol (FastAPI, header X-Webhook-Secret) → returns run_id, the review runs in the background.
Administrative Knowledge Base
  • Checklist ADMIN-CHK-01..15
  • Title, version, date, NCT id, PI, sponsor
  • Most serious: consent form, insurance, readable PDF
  • Required sections, appendices
Scientific Knowledge Base
  • SPIRIT checklist SPIRIT-01..33
  • ICH-GCP E6(R3) GCP-01..12
  • ClinicalTrials.gov record by NCT id (API v2)
  • Human-approved lessons (long memory)
Input
📄
Protocol PDF
clinical trial protocol
+
Optional metadata
NCT id · submitter · source (drive / email / webhook)
1Coordinator Agent · intake
  • Text extraction per page (PyMuPDF)
  • Metadata by regex: NCT, version, date, PI, sponsor, phase
  • 29 deterministic rule checks (code, no LLM) = Rule-Based Baseline
  • Opens the run on the Blackboard, routes to agent 2
Output: ReviewState + rule findings (verified by construction)
2Administrative Review Agent
  • Format and completeness vs administrative checklist
  • Adds context findings the rules cannot see (version mismatch, missing appendix, wrong consent language)
  • Evidence auto-verified in code (quote located? code valid?)
  • accepted = 100% complete (any verified finding returns it)
Output: AdminReport JSON (accepted, checklist, findings)
3Scientific Review Agent
  • Fetches ClinicalTrials.gov record, compares enrollment, phase, outcomes, sponsor
  • SPIRIT / ICH-GCP review: omissions, unjustified sample size, randomisation, safety
  • Internal contradictions between sections (quotes both places)
  • On REVISE: answers each critic request, re-emits findings
Output: ScientificReport JSON (findings, registry comparison, open questions)
4Scientific Critic Agent
  • Code first: is each quote really on that page? is the guideline code real?
  • One verdict per finding: verified / revise / unverified / rejected, may change severity
  • Lists issues the reviewer missed
  • Proposes reusable lessons → human approval (HITL memory)
Output: CriticReport JSON (verdicts, missed issues, proposed memory)
1Coordinator Agent · final
  • Anything still open → UNVERIFIED (human)
  • Decision: PASS / NEEDS_HUMAN_REVIEW / MAJOR_CONCERNS / RETURNED_ADMIN
  • Executive summary for the committee coordinator
  • Writes 3 Markdown reports + findings.json + state.json
  • 📧 Email to the boss with the reports attached (also on administrative rejection)
Output: FinalSummary + reports + email
Shared State / Blackboard (LangGraph ReviewState): findings · evidence (page + quote) · status · critic notes · revise requests · full trace  |  3-layer memory (SQLite): short = run messages · long = lessons proposed by agents, approved by a human · historical = every LLM call with tokens and cost
